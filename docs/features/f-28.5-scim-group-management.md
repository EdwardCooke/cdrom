# F-28.5 · SCIM group management

> Part of [F-28 · SCIM user provisioning](f-28-scim-provisioning.md) · Phase 6 — Authentication · [Feature index](../Features.md)

**What.** The `/Groups` resource endpoints plus the machinery that turns
corporate group membership into Cdrom authorisation: `POST/GET
/scim/v2/Groups`, `GET/PUT/PATCH/DELETE /scim/v2/Groups/{id}`, a lightweight
group store, and the **group→role mapping applicator** that computes each
SCIM-managed user's derived role set from the configured
`idp.scim.group_role_mappings` (F-28.1). Stretches optionally to F-27
approval-group targeting.

**Why.** Enterprises express entitlements as group membership (“admins”,
“deployers”, “approvers”). Supporting `/Groups` lets the corporate IdP sync
those memberships natively, and the mapping layer translates them into F-14
roles so authorisation tracks the directory with nobody touching Cdrom. This
pairs with F-14's JWT claim mapping: the corporate IdP both provisions (SCIM)
and authenticates (OIDC group claims), and the two stay consistent.

**Storage.** A new `IDPGroup` entity (`internal/models`, registered in
`All()`): `ID` (stable numeric PK, the SCIM `Location`), `DisplayName`
(unique), `Description`, `Members` (many-to-many with `IDPUser`),
`CreatedAt`/`UpdatedAt`. Groups are **hard-deletable** (contrast with users):
audit traces attach to users (actors), not groups, and a deleted group can be
recreated — so no tombstone machinery is needed for groups.

**Endpoint semantics.**
- `POST` — create a group (embedded members processed); duplicate
  `displayName` ⇒ 409.
- `GET` (collection) — paginated `ListResponse`; filter subset: `displayName
  eq X`, `members[value] eq X` (contains).
- `GET {id}` — members expanded to `{$ref, value, displayName}`.
- `PUT` — replace group attributes and the full member set.
- `PATCH` — ops on `members` (`add`/`remove`) and `displayName`/
  `description` (`replace`).
- `DELETE` — remove the group and revoke its derivations (affected users
  recomputed).
- Unknown id ⇒ 404; conflicts/errors are RFC 7644-shaped (F-28.1 encoder).

**Mapping application.** Deterministic, idempotent, replay-safe:
- Derived roles wanted for a SCIM-managed user = the **union** of the mapped
  roles over all groups the user belongs to (per
  `idp.scim.group_role_mappings`).
- A SCIM-managed user's full role set = the default/base role ∪ derived roles.
  (Consistent with F-28.4: SCIM users accumulate no manual role grants, so no
  per-contributor bookkeeping is needed.)
- Trigger points: group member add/remove (`PATCH`/`PUT`), group deletion,
  user provisioning with embedded `groups`, and mapping evaluation on each
  sync. Changes are diffed into the user's stored roles; replay converges to
  the same state.
- Edge rulings: leaving one of several groups deriving the same role keeps
  the role (union semantics); unmapped groups are stored inertly (membership
  recorded, no authorisation effect).
- **Stretch**: a mapping entry may target an F-27 approval group (group name
  → approval-group name) instead of an F-14 role, mirroring membership there.

**Scope.**
- `internal/models` — `IDPGroup` + member associations; migrated via `All()`.
- `proto/cdrom/db/v1/db.proto` + `internal/services/database` — `IDPGroup`
  message + `CreateGroup` / `ListGroup` / `GetGroup` / `UpdateGroup` /
  `DeleteGroup` RPCs (hard delete).
- `internal/idp` (`scim_groups.go`) — the `/Groups` routes, Group-schema
  codecs, filter/pagination (shares the F-28.4 list plumbing).
- `internal/idp` (`scim_mapping.go`) — the mapping applicator above (invoked
  from both the group and user handlers).
- F-15 audit — group mutations (create/delete/member-changes) and the
  resulting role diffs write events (actor = the SCIM service).
- `ui/` (minor) — a group list with memberships and mapping annotations
  (nice-to-have tier).

**Acceptance criteria.**
- [ ] `/Groups` CRUD honours the RFC 7643 Group schema (`displayName`,
      `members[$ref/value/displayName]`); errors and pagination match the
      `/Users` conventions.
- [ ] Member add/remove via `PATCH` ops updates the group atomically and
      re-applies the mapping.
- [ ] Configured group→role mappings drive SCIM-managed users' role
      computation deterministically: joining a mapped group grants the role;
      unions across multiple groups are honoured.
- [ ] Leaving one of several groups that derive the same role keeps the role.
- [ ] Deleting a group revokes its derivations (affected users recomputed).
- [ ] Unmapped groups are stored without authorisation effects.
- [ ] Unknown group ids return 404 SCIM-errors; duplicate `displayName`
      returns 409.
- [ ] Group mutations and resultant role changes write audit events.
- [ ] *(Stretch)* F-27-targeted mapping entries mirror membership into the
      approval-group store.
