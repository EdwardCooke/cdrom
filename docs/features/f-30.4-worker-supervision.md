# F-30.4 · Agent subprocess & supervision channel

> Part of [F-30 · Agent credentials & the agent/worker topology](f-30-agent-credentials-and-topology.md) · Phase 8 — Target credentials & execution topology · [Feature index](../Features.md)

**What.** The topology change: the agent stops executing jobs in-process and
instead **supervises a per-job worker subprocess**. On each assignment the
agent: (1) checks its **launch ledger** — `(job_id, attempt)` already
claimed/spawned ⇒ drop (duplicate delivery, F-23 nudges); (2) calls
`StartJobExecution` **itself**, presenting its agent credential — acquiring
the execution and receiving the freshly minted **job token** (the response
carries no payload; the agent never hydrates spec or secrets); (3) spawns
the worker with the mandate **in the environment only** — never in argv
(argv is world-readable via `/proc/*/cmdline` and process listings; env is
not). Spawn is `os/exec` with detached I/O (portable Win/Linux); the agent
records the child in the ledger + live-child map.

The worker's first API call is `GetJob` presenting the job token: the API
verifies the token, ties it to the mandated job, and returns the hydrated
payload (spec, upstream outputs, decrypted secrets). The old mint-on-call
behavior of `GetJob` (coining a token for an unidentified caller trusting
the transport) is **retired** — job tokens originate only from the agent's
credentialed `StartJobExecution`. The worker then executes the job talking
**directly** to the API (Option-A topology: targets talk only to the API),
reports its own status, and exits. The agent is a **dumb babysitter**: it
observes child liveness, relays cancellation **opportunistically** (the
worker's own API status poll remains the authoritative cancellation path,
F-05), reports abnormal child deaths, and adopts nothing else of the
execution.

**Canonical env contract** (the future Kubernetes agent emits exactly these
Pod env vars):

| Var | Req | Meaning |
|---|---|---|
| `CDROM_WORKER_JOB_ID` | ✔ | Mandated job |
| `CDROM_WORKER_JOB_TOKEN` | ✔ | Job token minted by the agent's `StartJobExecution`; the worker presents it to `GetJob` (payload claim) and every job-scoped RPC |
| `CDROM_API_ADDR` | ✔ | API gRPC address |
| `CDROM_PARENT_GRPC_ADDR` | ✔ | Loopback address of the agent's local channel |
| `CDROM_WORKER_ROOT` | – | Staged-work-area base (defaults OS temp; tmpfs warning kept) |
| `CDROM_TLS_CA_FILE` | – | Verifies the API server cert |
| `CDROM_LOG_*` | – | Inherited logging conventions (the worker exports no `/metrics` of its own; it reports via `Telemetry`, below) |

Deliberately absent from env: the agent credential (the worker never needs
it) and the payload (claimed from the API with the job token — never through
env, argv, or the local channel).

**Local gRPC channel** (`proto/cdrom/supervision/v1`, loopback TCP, the
address chosen by the agent at boot and passed in env). The worker **dials**
the agent and keeps the connection for its whole life; both verbs ride that
single **outgoing** channel — gRPC/HTTP2 multiplexes concurrent calls in
both directions on one connection, so no reverse dial (and no agent-side
**listener**) is needed. Two verbs:

1. `Signals(open stream) ← {Cancelled}` — agent-initiated **server stream**:
   opportunistic early notice of a cancellation the agent saw on its
   `WatchJobs` stream. **Non-authoritative**: the worker's own 2-second
   status poll (against the API) remains the guaranteed path; the stream
   only shrinks reaction latency.
2. `Telemetry(push samples) → Summary` — agent-initiated **client stream**:
   the worker pushes compact metric samples (step transitions, log bytes,
   timings) on an interval and a **final flush before exit**, so even a
   millisecond-long job deposits a complete account. The agent folds the
   samples into its **own** exported series; nothing scrapes the worker
   directly. (Symmetry footnote: if the agent ever needs to *pull* from the
   worker, the worker can embed a small gRPC server and the agent dial it —
   HTTP2 channels are symmetric — but push beats pull here: no worker port
   to advertise, and identical behavior for a future k8s pod agent.)

Loopback **plaintext** is accepted (parity with local-dev legs); the channel
binds `127.0.0.1` only.

**Lifecycle & failure.** The agent waits on each child (portable
`Cmd.Wait`). **Normal exit** ⇒ bookkeeping only (the worker already
reported its terminal status to the API). **Abnormal exit** / non-zero
WITHOUT a reported terminal status ⇒ the agent calls
`ReportChildDeath(job, reason)` with its **agent credential**; the API
marks the execution **failed** (respecting F-05's terminal-immunity rule)
so the job fails fast instead of riding out the F-03 watchdog.
Graceful-stop ordering on agent shutdown: **drain** (let children finish,
bounded by a configurable grace) → **interrupt** → **kill** (portable
`exec.Command` semantics).

**Concurrency.** No **artificial cap** in v1: F-16's durable admission
already bounds how many jobs an agent group can hold concurrently, so the
assignment rate self-throttles. The ledger permits unlimited *distinct*
coordinates in flight; only same-coordinate repeats are dropped. The
load-bearing invariant **changes** here: duplication safety no longer rests
on "the process is serial" but on **seriality per `(job, agent, attempt)`
coordinate** — upheld primarily by the agent's launch ledger and defended by
a **partial unique index** on `job_executions (job_id, agent_name, attempt)`
(added via `AutoMigrate`); a constraint-violating insert declines as
`Started:false` exactly as the count-guard does. The migrated comment block
(from F-30.1) is updated to state this invariant.

**Identity.** Executions attribute to the **agent's registered name**
(children are anonymous to the API apart from their job token); step-barrier
participant accounting (per-job, keyed by agent name) and fan-out status
derivation behave exactly as today's per-agent accounting.

**Why.** Capacity + isolation + portability. One-resident-process-
one-job-at-a-time wastes multi-core hosts and couples a hung step to the
whole target; per-job subprocesses isolate faults (a hung step dies with its
process) and admit concurrency safely. Defining the handoff as env-vars +
loopback channel makes the contract infrastructure-neutral: a Kubernetes
agent fulfills the identical contract by emitting a Pod spec (env = the same
variables, "spawn" = scheduling the pod, channel reachable via Pod IP /
hostNetwork) — swapping supervisors without touching the worker or the API.

**Slices.** Sequential increments, each ending compiled, tested, and
demonstrable (checkpoint commit per slice):

- **Slice 1 — Spawn & payload claim.** The agent's launch ledger +
  `os/exec` spawn with the env-only mandate; `StartJobExecution` slimmed to
  return the job token only (hydration removed from the API response);
  `GetJob` mint-on-call retired (token-gated payload claim); the worker's
  claim-then-execute path. Demonstrable: e2e — assignment ⇒ spawn ⇒ claim ⇒
  execute (steps, logs, artifacts, approvals, barriers) ⇒ report ⇒ exit; an
  assertion scan confirms secrets/spec absent from argv, env, and the local
  channel; a duplicate delivery of the same `(job, attempt)` spawns at most
  one worker (ledger drop).

    otherwise the worker gets its own `cdrom.worker-<job>-<nonce>.log` and the
    agent folds it post-exit.
  - **Non-destructive cancel relay (S1 adjudication).** `cancelJob` only
    NOTICEs + logs: killing the worker would leave no one to REPORT the
    terminal status (the dead worker can't; the agent must not forge the

  - **Proto.** `Service Supervisor { ConnectJob(JobTicket)→ConnectionGrant;
    Signals(Empty)→stream Signal; Telemetry(stream Sample)→FlushAck }`;
    `Sample` oneofs `StepSample` / `BytesSample` (cumulative watermark) /
    `JobSample` (the final flush) / `NoticeSample` (RELAY ACK — see hazard
    ③). Streaming verbs are MODERN GENERICS (grpc-go v1.84): server
    signatures `Signals(*Empty, grpc.ServerStreamingServer[Signal]) error`,
    `Telemetry(grpc.ClientStreamingServer[Sample, FlushAck]) error` (reply
    via `SendAndClose`); client `Signals(ctx,in,…) (grpc.ServerStreamingClient[…],
    error)` / `Telemetry(ctx,…) (…) (error)` (terminating call
    `CloseAndRecv`). Server embeds `UnimplementedSupervisorServer`.
  - **Topology.** The channel listens on a CONFIGURED bind
    (`supervision_bind` / `CDROM_SUPERVISION_BIND`; default loopback
    `127.0.0.1:0` — the local-substrate posture, intra-host by construction);
    the ephemeral address is advertised via `CDROM_PARENT_GRPC_ADDR` in the
    spawn env — absent ⇒ the worker runs channel-less, TOTAL DEGRADATION, the
    channel NEVER gates the job. Admission = the agent's LIVE-CHILD check
    (the launch ledger is the custody proof; the loopback channel is
    intra-host, so the token is not re-verified). Peer association rides the
    CONNECTION's remote address (one worker = one connection; unassociated
    peers are refused). CRITICAL: the long-lived streams ride
    `context.Background()` — their lifetime IS the connection; binding them
    to the handshake's timeout context cancelled them the instant the
    constructor returned (latent bug, caught by `TestChannelEndToEndFold`).
  - **Relay semantics.** `cancelJob` broadcasts a `Cancelled` notice to the
    job's live coordinates (non-blocking, drop-on-full); the worker ACTS
    (same `cancel()` the poll drives) and ACKS the relay THROUGH THE
    CHANNEL (`NoticeSample(CANCELLATION_ACK)` riding Telemetry into the
    agent's durable `cdrom_agent_cancel_signal_acks_total`) — proof-of-
    delivery that outranks the worker's log line. The worker's 2 s status
    poll remains the AUTHORITY (F-05); the agent still does NOT kill the
    child (destructive interrupt ships Slice 3).
  - **Absorption.** The worker's `channelRecorder` (a `metrics.Recorder`)
    forwards step outcomes live, accumulates log bytes toward 5 s watermarks,
    and BUFFERS the final job account for the pre-exit flush (bounded 2 s
    ack wait; the flush precedes exit by construction — `defer sc.Flush()`
    sits after the terminal report). The agent's fold (`observeChild`): the
    final `JobSample` SUPERSEDES the exit-code inference (one record, not
    two); step samples land in `cdrom_agent_steps_total` / step durations
    (UNINFERRABLE from the exit code — the absorption discriminator); log
    bytes join `cdrom_agent_log_bytes_total`; acks join the new counter.
  - **LAUNCHER SEAM (substrate injection, 2026-11-11).** The agent's
    supervision CORE (launch ledger, live children, observation, metric
    roll-up, the supervision channel) is substrate-BLIND: it speaks only the
    `Child` / `Launcher` / `Mission` contracts (`internal/agent/launcher.go`).
    Bringing a worker UP is delegated to an INJECTED launcher — the default
    is the LOCAL launcher (`launcher_local.go`: `os/exec` fork, the
    canonical env contract, the platform detachment, the worker's log
    placement). Building the Kubernetes piece is a LAUNCHER SWAP (emit a Pod
    spec instead of forking; realize `Child` over the Pod's lifecycle), not a
    rewrite of the agent. Companion seam: the channel's CONFIGURABLE BIND
    (above) lets a node-network agent expose the channel to Pod workers that
    cannot reach its localhost. Installed by `cmd/agent` (injects
    `NewLocalLauncher` + the config's bind); guarded by
    `TestChannelDefaultsToLoopback` / `TestChannelHonorsConfiguredBind`.
  - **RESUME ADMISSION (k8s-restart story, item A, 2026-11-12).** The agent
    can restart mid-job (k8s: Pod eviction / rollout). The channel
    relationship is made RESUMABLE so a worker reconnects to a fresh agent
    instance instead of running channel-less:
    - `ConnectJob` now admits on EITHER lane — COLD (the coordinate is a
      LIVE CHILD; the ledger is the custody proof) or RESUME (the agent
      restarted and holds no live child; the ticket is VALIDATED FOR
      CONSISTENCY: `job_id != 0` AND the token's `agent_name` claim —
      decoded UNSIGNED — equals the agent's OWN registered name). The grant
      echoes `resumed` (observational). Predicate: `admitChannelWorker`
      (guards `TestChannelColdAdmitsLiveChildOnly` /
      `TestChannelResumeAdmitsConsistentForeignChild`).
    - **NAME STABILITY (2026-11-12).** The default `agent_name` is now the
      HOSTNAME (mirrors the worker's default), so the resume lane's compare
      target is whatever the fresh instance REGISTERS. On platforms whose
      host name churns across restarts (typical containers / k8s) the
      operator MUST pin a stable `agent_name` — otherwise the resume lane
      REFUSES the rightful ticket (name mismatch) and the worker degrades
      to channel-less. The e2e harness pins `CDROM_AGENT_NAME=agent-1`
      likewise (the credential is issued to the presenting name).
      DISTINCTNESS is the companion clause: two agents sharing a name
      sabotage each other (watcher eviction flapping, mutual execution
      abandonment) — enforcement is parked as F-31 §4.
    - The worker's ticket carries `agent_name` (its attribution name,
      decoded from its own job token — the very name the API stamped when
      THIS agent started the execution), and its connect is RESILIENT:
      transient failures (agent not listening yet / just restarted) retry
      with backoff within a bounded budget; a PERMANENT refusal (the agent
      answered and declined the ticket) stops immediately.
    - SECURITY NUANCE (honest limitation): the resume lane's custody proof
      is the UNSIGNED `agent_name` decode. Sound on LOOPBACK (holding a
      valid token for this agent implies owning one of its workers); WEAKER
      on a NETWORK-reachable bind (an attacker with any valid token minted
      for this agent could attach a telemetry/signals stream to a
      coordinate). Landed in SLICE 3 (item B3): the routable posture now
      VERIFYs the ticket via the API's `VerifyJobToken` attestation (the
      agent holds no JWKS) and admits only tickets naming THIS agent.
    - SCOPE OF A: the resumable PROTOCOL + admission + startup-resilient
      connect. The worker's MID-LIFE reconnector (re-dialing when the agent
      dies while it runs) and the agent's ORPHANED-OBSERVATION ADOPTION
      (rolling a rejoined child's metrics into the fresh instance's series)
      ship with SLICE 3 (item B) — without B, a resumed worker's telemetry
      has no observing instance to land in, so A alone is foundational.
  - **Hazards met (worth remembering).** ① The shared `agent.log` suffers
    an ENVIRONMENTAL PATHOLOGY under the harness's concurrent readers: the
    prefix mutates AND lines occasionally vanish outright (confirmed live
    seconds ago, gone from the frozen copy) — e2e 26 therefore TIERS ITS
    PROOFS: HARD verdicts ride durable media (metrics, REST state, the ack
    counter); log-derived timings are SOFT corroboration, tolerated-vanished.
    ADDENDUM (2026-11-13): the DEDICATED s3-agent logs (e2e 27) suffer NONE
    of this — the worker's stderr IS the agent's log fd (fd inheritance
    through setsid+detach; logging opens O_APPEND), so a surviving worker
    keeps appending to the predecessor's file and its reconnection line
    arrives deterministically at the 15 s base delay; e2e 27's checks
    against those files are HARD. Three earlier "tolerated-vanished"
    readings of that line traced to an unescaped-parenthesis ERE pattern
    (`RECONNECTED (mid-life)` compiled to `RECONNECTED mid-life`), not to
    log volatility.
    ② A `shell` step honours cancellation LAZILY (forked descendants hold
    the stdout pipe; the handler's Wait blocks until they exit naturally) —
    parked as F-31 §3 with the process-group-kill proposal; e2e 26 uses a
    short sleeper and discloses the wart. ③ Relay-vs-poll RACE: when the
    relay wins, the worker's poller exits QUIETLY (its context is already
    done) — the `"worker: job cancelled"` line appears only when the poll
    wins; the e2e authority proof is thus the worker's SELF-REPORTED
    terminal status (either path wakes the same `cancel()`), with the
    poll-wins path unit-pinned. ④ Stale doc contradictions ("INTERRUPTS THE
    CHILD") purged from `internal/agent` (three sites).

    OBSERVATION ADOPTION — on boot, the fresh instance discovers the

    adoption, a resumed worker's telemetry has no observing instance to
    land in (A alone is foundational). (3) Harden the resume lane's custody
    proof for the ROUTABLE posture (verify the token's signature, not just
    the unsigned `agent_name` decode — see the Slice 2 security nuance).

    Signals Recv error / connection death) KICKS the reconnector (cond-var
    wake — no epoch/channel races): it re-dials the ADVERTISED address on a

    channel-less-forever (permanent REFUSAL still yields nil — an answering

  - **SEQUENCED SAMPLES (idempotent rejoin).** Every sample (Step/Bytes/

    can never double-book a sample (bytes watermarks and the single-final
    invariant compose with it). The final `JobSample` grabs its seq at
    FLUSH time (after the burst's bytes sample) so it is never swallowed.
  - **ITEM B2 — ORPHANED-OBSERVATION ADOPTION (agent).** The register-time
    BLIND `AbandonAgentExecutions` is RETIRED (doctrine inversion: the agent
    is the ORACLE of its own lineage — it ADOPTS, it does not burn). At
    boot the `adoptionSweep` (background; `Stop` waits for it) calls the
    API's `DiscoverAgentExecutions` wrapper (credential-bound to the
    presenter — an agent can only enumerate its OWN lineage) and, for each
    still-running execution younger than the horizon (default 1 h),
    RESERVES the ledger coordinate (a redelivery of the same job is DROPPED
    — the worker is still running) + marks it ADOPTED (third admission
    lane: live-child ⟶ adopted ⟶ name-consistency). Too-old orphans are
    deemed dead and FAILED via `ReportChildDeath` (the fast-failure escape
    hatch — the alternative is the F-03 watchdog's ride-out). Settlement:
    an adopted worker has NO local child to Observe — its FINAL FLUSH is
    the completion signal: the channel's `Telemetry` end (with a final
    seen) invokes the agent's `settleAdopted` (rolls the account into THIS
    instance's series, frees the ledger, discharges the adoption).
  - **ITEM B3 — ROUTABLE RESUME-LANE HARDENING.** The agent holds no JWKS
    (it cannot verify RS256 itself), so the API gained `VerifyJobToken`
    (identity verb — the presenter's agent credential; TRI-STATE reply:
    `enabled=false` = attestation unavailable (job-token auth off) ⇒ the
    caller keeps its unsigned decode; `valid` + the VERIFIED `agent_name`
    claim otherwise). `admitChannelWorker` consults it ONLY when the
    channel's bind ESCAPES loopback (`routableChannel()`): the custody
    proof upgrades from the unsigned decode to the API's signature
    verification (the Slice 2 security nuance is closed for the routable
    posture; loopback keeps the cheap decode — intra-host, holding a valid
    token for this agent implies owning one of its workers).
  - **Supporting cast.** `Child.ID() string` generalized (was `Pid() int` —
    a Pod UID is not an integer; callers log/report, never parse);
    `localChild.Interrupt()` (the stop ordering's middle rung) delegates to
    the PLATFORM PAIR of `attachDetachment` — `interruptProcessTree`:
    LINUX signals the child's WHOLE process group (Setpgid ⇒ group id = the
    child's pid; `syscall.Kill(-pid, SIGINT)` — the worker's own grandchild
    commands hear it too); WINDOWS generates a CtrlBreak CONSOLE EVENT for
    the child's process group (`GenerateConsoleCtrlEvent(CTRL_BREAK_EVENT,
    groupId=pid)` via a lazy kernel32 proc — `Process.Signal(os.Interrupt)`
    is UNIMPLEMENTED on Windows (ErrUnsupportedSignal) and on Linux reaches
    only the direct child); OTHER platforms signal the direct child.
    Best-effort on every leg: the kill stage (Terminate) is the guarantee.
    The `JobExecution` model + ledger comments carry the sharpened invariant.
  - **Known edges (honestly filed).** ① The worker's reconnector persists
    against an EPHEMERAL address (local posture) at a negligible refused-
    connect cost — harmless, disclosed. ② A successor that boots PAST an
    orphan's horizon fails it (the worker then runs channel-less to
    completion — the job still finishes; the execution's terminal report
    is immune). ③ `TestIDPGroupListPredicates` flakes intermittently under
    full-package load (fixtures are hermetically isolated — pre-existing,
    disclosed, not induced). ④ The adoption sweep's 2 s settle delay trades
    a hair of boot latency for not racing the registration's own writes.

Dependency: S1 → S2 → S3 strictly. Requires F-30.1 (names) and F-30.3
(the agent credentials its `StartJobExecution`).

**Scope.**
- `internal/agent` — supervisor: launch ledger, live-child map, `os/exec`
  spawn, local-channel server, `ReportChildDeath` caller, telemetry roll-up.
- `internal/worker` — runner: payload claim (`GetJob` with job token),
  channel client (`Signals` receiver, `Telemetry` emitter), final flush.
- `proto/cdrom/supervision/v1` (new) + `proto/cdrom/api/v1/api.proto` —
  `StartJobExecutionResponse` slimming, `GetJob` auth semantics,
  `ReportChildDeath`.
- `internal/services/database` — partial unique index on `job_executions`
  (AutoMigrate).
- `internal/api` — `ReportChildDeath` handler (validate the agent group
  actually serviced the job before trusting it as a status oracle).
- `scripts/e2e` — spawn/kill/concurrency scenarios.

**Design decisions.**
- **Mandate in environment only.** argv is world-readable; env is not. The
  contract doubles as the future Pod spec — portability by construction.
- **The agent initiates, the worker claims, the agent never hydrates.**
  Secrets travel directly between API and worker over their own connection;
  the loopback channel carries cancellation relay and telemetry only.
- **Push-beats-pull telemetry.** One outgoing connection from the
  short-lived side; no listener port to advertise; identical story for a k8s
  pod agent.
- **Serial per coordinate, not globally.** Concurrency safety rests on
  coordinate uniqueness (ledger primary, index defensive), freeing per-host
  parallelism while preserving the exact invariant the 2026-11-07 flake
  taught.
