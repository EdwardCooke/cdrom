# F-21.3.2 · Credential matching & use

> Part of [F-21.3 · Source credentials](f-21.3-source-credentials.md) · Part of [F-21 · Config as code](f-21-config-as-code.md) · Phase 4 — Delivery & observability · [Feature index](../Features.md)

This sub-feature is the **credential matching** used by the sync routine
(F-21.5.2): when a source is synced, the API selects the credential to use (an
explicit `credential` name on the source, else the longest matching `prefix`),
decrypts its secret material, and hands the plaintext to the source-fetcher
(F-21.2) for that one fetch. The fetcher never stores a credential.

**Why.** A source may be private, so the API must pick the right credential for
it. Matching by an explicit name (when the source names one) or by the longest
matching `prefix` (otherwise) keeps the selection deterministic and
diagnosable, and handing the plaintext to the fetcher for a single fetch keeps
the secret out of the fetcher's on-disk state and out of the API's
configuration.

**Depends on.** [F-21.3.1](f-21.3.1-source-credential-model.md) (the
`SourceCredential` model) and F-12 (the secret store the API decrypts with).

**Scope.**
- `internal/api` — the credential **matching** used by the sync routine
  (F-21.5.2): an explicit `credential` name on the source, else the longest
  matching `prefix`; the API decrypts the chosen credential's secret material
  for that single fetch and hands the plaintext to the source-fetcher
  (F-21.2) over the gRPC call.

**Acceptance criteria.**
- [x] When a source is synced: if the source names a `credential`, that
      credential is used; otherwise the source's `reference` is matched against
      every credential's `prefix` and the **most specific (longest) matching
      prefix** wins; a source matching no credential uses no credential (a
      public source).
- [x] The chosen credential's secret material is decrypted by the API for that
      single fetch and handed to the source-fetcher (F-21.2); it is not
      persisted anywhere else and is not logged.
- [x] A credential that fails to authenticate (a rotated token, a revoked key)
      surfaces as a sync failure on the source state (F-21.5) and is visible in
      the UI, so a stale credential is diagnosable without a repo checkout.
      (Implemented with the minimal F-21.5.1/F-21.5.2 slice: a source refresh
      records the fetch error on the source state's `last_error`, surfaced via
      `GET /api/pipelines/{id}/source`.)

## Matching and use

When a source is synced (F-21.5.2):

1. If the source names a `credential`, that credential is used.
2. Otherwise the source's `reference` is matched against every credential's
   `prefix`; the longest matching prefix's credential is used.
3. If neither applies, the fetch runs unauthenticated (a public source).

The chosen credential's secret material is decrypted by the API for that single
fetch and handed to the source-fetcher (F-21.2, over the gRPC call); it is not
persisted anywhere else (the fetcher holds no credentials at rest) and is not
logged. A
credential that fails to authenticate (a rotated token, a revoked key) surfaces
as a sync failure on the source state (`last_error`) and is visible in the UI,
so a stale credential is diagnosable without a repo checkout.

## Design decisions (folded into AGENTS.md / Architecture.md)

- **Credential matching is by explicit name or longest matching prefix.** When
  a source is synced, the API uses the credential the source names (an explicit
  override) or, failing that, the credential whose `prefix` is the longest
  match against the source's `reference`; a source matching no credential runs
  unauthenticated (a public source). The chosen credential's secret material is
  decrypted by the API for that single fetch and handed to the source-fetcher
  (which stores nothing) — it is never logged or persisted elsewhere.
- **New logic (this sub-feature).** Credential matching in the API (explicit
  `credential` name, else longest matching `prefix`) used by the sync routine
  (F-21.5.2); the API decrypts the chosen credential for a single fetch and
  hands the plaintext to the source-fetcher (F-21.2).
