# F-30.1 · Role swap & wholesale rename

> Part of [F-30 · Agent credentials & the agent/worker topology](f-30-agent-credentials-and-topology.md) · Phase 8 — Target credentials & execution topology · [Feature index](../Features.md)

**What.** A **behavior-preserving** nominal inversion: the long-lived
registered execution target is renamed **agent** everywhere (binary, package,
model, proto, config, permission, event, metric, docs), and the ephemeral
one-job-per-process executable is renamed **worker**. Binaries keep their
paths; **contents swap** — `bin/agent` becomes the long-lived supervisor
entrypoint, `bin/worker` the ephemeral runner entrypoint. At THIS slice the
supervisor still executes jobs directly in-process (it does not yet spawn
children — that arrives in F-30.4), and the ephemeral runner is still
launched externally with a job-id env var (today's agent behavior, verbatim).
Only the NAMES change; every observable behavior is provably identical.

Wire/model/field renames (generated code regenerates via `make proto`):

| Concern | Was | Becomes |
|---|---|---|
| Registered entity (model/message/columns) | `Agent` / `agent_name` | `Agent` / `agent_name` |
| Grouping construct | worker group (`AgentGroup`) | agent group (`AgentGroup`) |
| Lifecycle RPCs | `RegisterAgent` / `DeregisterAgent` | `RegisterAgent` / `DeregisterAgent` |
| Stream/poll fields | `WatchJobsRequest.agent_name`, `ListPendingJobsRequest.…` | `agent_name` |
| Execution coordinate | `(job_id, agent_name, attempt)` | `(job_id, agent_name, attempt)` |
| Config (long-lived) | `CDROM_WORKER_{NAME,GROUP,ENVIRONMENTS,LABELS,ROOT}` | `CDROM_AGENT_{NAME,GROUP,ENVIRONMENTS,LABELS,ROOT}` |
| Config (ephemeral) | `CDROM_AGENT_{JOB_ID,NAME}` | `CDROM_WORKER_{JOB_ID,NAME}` (F-30.4 widens this set) |
| RBAC areas | `agents.can-view`, `agent-groups.can-{view,manage}` | `agents.can-view`, `agent-groups.can-{view,manage}` (`agents.can-manage` registered for F-30.2) |
| WS/event nouns | `worker` events, snapshot `workers[]` | `agent` events, snapshot `agents[]` |
| Label precedence | `worker > worker group > …` | `agent > agent group > …` |
| Metrics families | `cdrom_worker_*` (resident) | `cdrom_agent_*` (resident); the ephemeral runner keeps `cdrom_worker_*` (rolled up in F-30.4) |
| Docs/terms | "worker" = resident | "agent" = resident; "worker" = per-job executable |

The load-bearing duplicate-delivery guard comment in the Database service
moves (REWORDED) to the supervisor package; the invariant itself is
UNCHANGED at this slice (the resident process is still serial per job) —
F-30.4 mutates it.

**Why.** Vocabulary stability for the downstream slices. A half-renamed
vocabulary (two meanings of "worker") is worse than churning generated code
once. Landing the rename FIRST means F-30.2–F-30.4 speak the final nouns and
their diffs contain new MECHANISMS only — not interleaved rename-plus-change
noise — and the e2e suite proves behavioral equivalence at every intermediate
rung.

**Slices.** Sequential increments, each ending compiled, tested, and
demonstrable (checkpoint commit per slice):

- **Slice 1 — Dataplane rename.** Models (`Agent`, `AgentGroup`,
  `agent_name` column tags), `db.proto` + `api.proto` message/field/method
  renames, `make proto` regen, `AutoMigrate` (fresh columns — see
  pre-existing data below), Database-service and scheduler renames.
  Demonstrable: unit/integration suites green against SQLite; the stack boots
  and the (now-named) agent registers, watches, and executes a job exactly as
  before.
- **Slice 2 — Process & surface rename.** Swap `cmd/agent` ↔ `cmd/worker`
  contents; rewrite `internal/agent` (supervisor home) and `internal/worker`
  (runner home, absorbing today's `internal/agent` execution logic); config
  keys flipped; RBAC catalog constants renamed; EventHub nouns + snapshot
  arrays renamed; metrics families reassigned; scripts/e2e, docker-compose,
  Dockerfile, `local/env`, and docs (`AGENTS.md`, `Architecture.md`,
  `Monitoring.md`, `HighAvailability.md`) updated in the same change.
  Demonstrable: FULL e2e suite green under the new names; the terminological
  audit below passes.

Dependency: S1 → S2 strictly (S2's greps are meaningless until the dataplane
compiles under the new names).

**E2E discipline (both slices).** The e2e harness (`scripts/e2e.sh`,
`scripts/e2e/lib.sh`, every `NN-*.sh`) is adapted IN LOCKSTEP with each
slice — binary invocations, `CDROM_*` env spellings, and the websocket
snapshot/assertion field names it parses — so the FULL suite is green at
each slice checkpoint, not merely at the end. A slice that lands with a red
e2e suite is unfinished.

**Scope.**
- `internal/models` — `Agent`/`AgentGroup` entities + `agent_name` tags,
  registered in `All()`.
- `proto/cdrom/db/v1/db.proto`, `proto/cdrom/api/v1/api.proto` +
  `internal/gen/` (regenerated) — entity/message/field/rpc renames.
- `internal/services/database`, `internal/services/scheduler`, `internal/api`
  — consumers of the renamed surface (hub, event nouns, guards).
- `cmd/agent`, `cmd/worker`, `internal/agent`, `internal/worker` — contents
  swapped; packages rewritten around the new homes.
- `internal/config` — `CDROM_AGENT_*` / `CDROM_WORKER_*` key families.
- `internal/authz` — permission constants (`agents.*`, `agent-groups.*`).
- `internal/metrics` — family reassignment.
- `scripts/`, `local/`, `Dockerfile`, `docs/` — narrative + harness renames.

**Design decisions.**
- **Registry reset on upgrade is ACCEPTED** (no backwards-compatibility
  obligation, per the F-30 charter). Column/tag renames make GORM create
  fresh columns; rows in upgraded databases lose registry/history linkage.
  Upgrades are DOCUMENTED as resetting the agent registry and
  execution-history join columns; an appendix SQL sketch (copy-forward) ships
  for operators wanting continuity. Fresh deploys are unaffected.
- **Behavioral equivalence is the bar.** Nothing in this slice changes WHAT
  happens — only WHOSE NAME IT HAPPENS UNDER. The e2e suite (adapted for
  names) is the proof vehicle; a divergence found here is a bug in the rename,
  not a feature.

**Acceptance criteria.**
- [x] Behavioral equivalence at EVERY slice checkpoint: the e2e suite
      (adapted in lockstep for names) is green after Slice 1 and after
      Slice 2 — not only at the end of the sub-feature. _(Land: full suite
      `e2e PASSED` on the final S1+S2 state; the intervening edits after the
      run were comment-only, so the green covers the shipped state.)_
- [x] The long-lived process registers AS AN AGENT (datamodel, RPCs, events,
      metrics) and executes jobs end-to-end; the ephemeral process executes a
      single job and exits — behaviors indistinguishable from pre-slice
      (e2e suite green modulo names). _(Suite exercises both roles: the
      resident agent in every scenario; the ephemeral worker launcher in the
      externally-sourced-pipeline scenario.)_
- [x] Terminological audit: no residual "worker" denoting the resident
      process in code identifiers, protos, config keys, permissions, events,
      metrics, or docs (grep-clean across `cmd/`, `internal/`, `proto/`,
      `docs/`, `scripts/`, `ui/`). _(Polarity sweeps clean: zero
      long-lived-worker / ephemeral-agent violations; the only surviving
      `worker_name` is the INTENTIONAL new ephemeral yaml tag.)_
- [x] Cross-platform builds green (`GOOS=windows go build ./cmd/...`).
- [x] Upgrade-path documentation states the registry reset; the copy-forward
      SQL sketch is reviewed (shipping it as a tested migration is an open
      item on the F-30 overview). See Appendix A.

## Appendix A — Copy-forward sketch (optional continuity on upgrade)

After upgrading, `AutoMigrate` has added the fresh `agent_name` columns
while the OLD `worker_name` columns still hold the pre-swap data. To carry
continuity forward (registry + execution history), run BEFORE the first
stack start on the upgraded schema:

```sql
-- PostgreSQL flavor (adjust dialect/table names to taste; SQLite lacks
-- ALTER TABLE DROP COLUMN in older versions — recreate the table instead).
UPDATE agents         SET agent_name = worker_name WHERE worker_name IS NOT NULL;
UPDATE job_executions SET agent_name = worker_name WHERE worker_name IS NOT NULL;
ALTER TABLE agents         DROP COLUMN worker_name;
ALTER TABLE job_executions DROP COLUMN worker_name;
```

Live agent registry rows are lost either way (connections die on upgrade);
this sketch salvages HISTORICAL joins only. Shipping it as a tested
migration script remains an open item on the F-30 overview.
