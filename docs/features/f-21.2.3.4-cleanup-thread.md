# F-21.2.3.4 · Cleanup thread

> Part of [F-21.2.3 · Git repository cache](f-21.2.3-git-repository-cache.md) · Part of [F-21.2 · Source-fetcher service](f-21.2-source-fetcher.md) · Part of [F-21 · Config as code](f-21-config-as-code.md) · Phase 4 — Delivery & observability · [Feature index](../Features.md)

**What.** The **cleanup thread** — a background goroutine started with the
service that periodically walks the cache (F-21.2.3.1) and prunes repositories
that have gone inactive for more than 24 hours, plus orphaned directories that
have no index entry. It removes the index entry **before** the directory so a
concurrent fetch can never be pointed at a directory that is being deleted, and
it skips a repository that is currently locked (F-21.2.3.3).

**Why.** The cache is a rolling 24-hour window (F-21.2.3.2): repositories that
are no longer used must be pruned so the cache does not grow without bound, and
directories left behind by an interrupted clone (a crash mid-clone) must be
swept so the cache root stays clean. Removing the index entry first makes
pruning safe against a concurrent fetch; skipping locked repositories makes it
safe against an in-progress fetch.

**Scope.**
- The **cleanup thread** (a background goroutine) that periodically walks the
  cache (on a fixed interval, e.g. hourly).
- Pruning of repositories inactive for more than 24 hours (index entry removed
  before the directory).
- Sweeping of orphaned directories (present under the cache root but with no
  index entry).
- Skipping repositories that are currently locked (F-21.2.3.3).

**Acceptance criteria.**
- [ ] A **cleanup thread** (a background goroutine) periodically walks the
      cache and deletes repositories that have been inactive for more than 24
      hours; before a directory is pruned, its entry is removed from the index
      file (F-21.2.3.1).
- [ ] The sweep **skips** a repository that is currently locked (a fetch in
      progress, F-21.2.3.3) and retries it on the next pass.
- [ ] The sweep also removes **orphaned directories** that exist under the cache
      root but have no index entry (e.g. a clone interrupted by a crash).
- [ ] Removing the index entry before the directory means a concurrent fetch can
      never be pointed at a directory that is being deleted — it sees no entry
      and clones a fresh one (F-21.2.3.2).

## The cleanup thread

A background goroutine started with the service periodically walks the cache
(F-21.2.3.1) (on a fixed interval, e.g. hourly) and prunes repositories that
have gone inactive:

- **Prune inactive repositories.** For every index entry whose last-accessed
  timestamp is more than 24 hours old, the cleanup thread first deletes the
  entry from the index file (an atomic rewrite, F-21.2.3.1) and only then
  deletes the repository's directory. Removing the index entry before the
  directory means a concurrent fetch can never be pointed at a directory that
  is being deleted — it sees no entry and clones a fresh one (F-21.2.3.2).
- **Skip locked repositories.** The sweep skips a repository that is currently
  locked (a fetch in progress, F-21.2.3.3) and retries it on the next pass, so
  it never deletes a directory a fetch is actively using.
- **Sweep orphaned directories.** The sweep also removes orphaned directories
  that exist under the cache root but have no index entry (e.g. a clone
  interrupted by a crash), so the cache root stays clean.

## Design decisions (folded into AGENTS.md / Architecture.md)

- **A background cleanup thread prunes the cache.** A background goroutine
  started with the service periodically walks the cache (on a fixed interval,
  e.g. hourly) and prunes repositories inactive for more than 24 hours, removing
  the index entry before the directory (so a concurrent fetch can never be
  pointed at a directory being deleted), skipping repositories that are
  currently locked (F-21.2.3.3), and sweeping orphaned directories that have no
  index entry.
- **New fields / RPCs / endpoints (this sub-feature).** The cleanup thread in
  `internal/services/pipelinesource` (a background goroutine that prunes
  inactive repositories and sweeps orphaned directories).
