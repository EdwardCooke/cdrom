# F-21.2.4.3 · File fetch client

> Part of [F-21.2.4 · Fetch clients](f-21.2.4-fetch-clients.md) · Part of [F-21.2 · Source-fetcher service](f-21.2-source-fetcher.md) · Part of [F-21 · Config as code](f-21-config-as-code.md) · Phase 4 — Delivery & observability · [Feature index](../Features.md)

**What.** The **`file` fetch client** — the client that serves a `file`
reference (F-21.2.2) by reading a file from the fetcher's host, resolved
against a configured local-filesystem root (`CDROM_PIPELINE_SOURCE_FILE_ROOT`).
The file is read directly from `<root><path>`; no network is involved and the
file is not cached. The client returns the file's mtime as the version
identifier and the SHA-256 of the content as the content hash. When no root is
configured the `file` kind is **disabled** and a `file:` fetch fails with a
clear error.

**Why.** Isolating the file fetch in its own client keeps the rest of the
service (the gRPC contract, F-21.2.1) thin and makes the file-specific behavior
— the rooted path resolution and the mtime version identifier — a single,
testable unit. Keeping the `file` kind rooted in a configured directory stops
the fetcher from reading arbitrary files on its host.

**Scope.**
- The **`file`** client in `internal/services/pipelinesource` — read a file
  from `<root><path>` where `<root>` is the configured local-filesystem root
  (`CDROM_PIPELINE_SOURCE_FILE_ROOT`); the resolved path must stay within the
  root.
- The version identifier — the file's mtime.
- The content hash — the SHA-256 of the file's content.
- `internal/config` — `CDROM_PIPELINE_SOURCE_FILE_ROOT` (unset = the `file`
  kind disabled).

**Acceptance criteria.**
- [ ] A file can be fetched from the **local filesystem** (a path resolved
      against the fetcher's configured filesystem root).
- [ ] The **`file`** client reads the file directly from `<root><path>`; no
      network is involved and the file is not cached. It returns the file's
      mtime as the version identifier.
- [ ] A **`file:`** reference is resolved against the fetcher's configured
      local-filesystem root (`CDROM_PIPELINE_SOURCE_FILE_ROOT`): a reference of
      `file:/shared-variables.yaml` with a root of `/shared` reads
      `/shared/shared-variables.yaml`, and the resolved path must stay within
      the root.
- [ ] When no root is configured, the `file` kind is **disabled** and a `file:`
      fetch fails with a clear error.
- [ ] The client returns the file's **content** and its **content hash**
      (SHA-256 of the content) alongside the file's mtime as the version
      identifier.

---

## The file fetch client

The `file` client serves a `file` reference (F-21.2.2) — a path — by reading a
file from the fetcher's host, resolved against a configured local-filesystem
root:

- **Rooted path resolution.** The file is read from `<root><path>` where
  `<root>` is the configured local-filesystem root
  (`CDROM_PIPELINE_SOURCE_FILE_ROOT`). For example, a reference of
  `file:/shared-variables.yaml` with a root of `/shared` reads
  `/shared/shared-variables.yaml`. The resolved path must stay within the root
  (a path that escapes the root is rejected), so the fetcher can read only
  files under that root — never an arbitrary path on its host.
- **No network, no cache.** The file is read directly; no network is involved
  and the file is not cached. This is the kind for a definition that is mounted
  into the fetcher's pod (e.g. a ConfigMap or a volume) and is "pulled" by
  re-reading the file.
- **Version identifier.** The response's version identifier is the file's
  mtime.
- **Content hash.** The response's content hash is the SHA-256 of the file's
  content.
- **Disabled without a root.** When no root is configured
  (`CDROM_PIPELINE_SOURCE_FILE_ROOT` unset), the `file` kind is **disabled**
  and a `file:` fetch fails with a clear error.

## Design decisions (folded into AGENTS.md / Architecture.md)

- **`file:` references are rooted.** A `file:` reference is resolved against a
  configured local-filesystem root (`CDROM_PIPELINE_SOURCE_FILE_ROOT`), so the
  fetcher can read only files under that root — never an arbitrary path on its
  host. With no root configured the `file` kind is disabled. The `file` client
  reads the file directly (no network, no cache) and returns the file's mtime
  as the version identifier.
- **New fields / RPCs / endpoints (this sub-feature).** The `file` fetch client
  in `internal/services/pipelinesource` (rooted path resolution, the mtime
  version identifier); and `CDROM_PIPELINE_SOURCE_FILE_ROOT` (unset = the
  `file` kind disabled) in `internal/config`.
