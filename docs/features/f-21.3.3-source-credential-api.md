# F-21.3.3 · Source-credential API (CRUD & redaction)

> Part of [F-21.3 · Source credentials](f-21.3-source-credentials.md) · Part of [F-21 · Config as code](f-21-config-as-code.md) · Phase 4 — Delivery & observability · [Feature index](../Features.md)

This sub-feature is the **source-credential API** — the CRUD endpoints that
manage `SourceCredential` rows (F-21.3.1), gated on RBAC permissions (F-14).
The API encrypts the plaintext secret material on create/update (via the F-12
store) and redacts it on read, so the plaintext is never returned to the UI.

**Why.** Credentials must be manageable at runtime (a rotated token, a new
private repo) without a redeployment, and the secret material must never leak
to the UI. Encrypting on write and redacting on read keeps the plaintext out of
the API's responses while still letting an operator see which sources a
credential covers (its `prefix`).

**Depends on.** [F-21.3.1](f-21.3.1-source-credential-model.md) (the
`SourceCredential` model) and F-14 (the RBAC permissions).

**Scope.**
- `internal/api` — the **source-credential** CRUD endpoints (the API encrypts
  the plaintext on create/update via the F-12 store and redacts it on read).
- `internal/api/server.go` — `GET/POST /api/source-credentials`,
  `GET/PUT/DELETE /api/source-credentials/{name}`.
- `internal/authz` — the `source-credentials.can-view` /
  `source-credentials.can-manage` permission pair (F-14).

**Acceptance criteria.**
- [x] `GET /api/source-credentials` lists credentials (secret material
      redacted); `POST` creates one (the body carries the plaintext secret
      material, which the API encrypts before storing); `GET/{name}` fetches one
      (redacted); `PUT/{name}` updates (re-encrypts the secret material);
      `DELETE/{name}` deletes (rejected with 409 if a source still references it
      by name — the guard counts the `PipelineSource` rows that name the
      credential, F-21.5.1).
- [x] The plaintext is **never returned to the UI** — a credential read back
      through the API shows its `name`, `kind`, `prefix`, `description`, and
      (for `git-https`) `username`, but the token / private key are redacted
      (and, for `http`, each header value is masked when its `sensitive` flag
      is `true`, returned in plaintext when it is `false`).
- [x] Listing requires `source-credentials.can-view`; create/update/delete
      require `source-credentials.can-manage` (admins have both). A change
      publishes a `source_credential` WS event so the UI stays current.

## API surface

- `GET /api/source-credentials` — list credentials (secret material redacted;
  each `http` header value is masked when its `sensitive` flag is `true`,
  shown in plaintext when it is `false`).
- `POST /api/source-credentials` — create a credential (the body carries the
  plaintext secret material, which the API encrypts before storing when it is
  marked sensitive).
- `GET /api/source-credentials/{name}` — fetch one (redacted, per the rules
  above).
- `PUT /api/source-credentials/{name}` — update (re-encrypts the secret
  material).
- `DELETE /api/source-credentials/{name}` — delete (rejected if a source still
  references it by name).

Listing requires `source-credentials.can-view`; create/update/delete require
`source-credentials.can-manage` (admins have both). A change publishes a
`source_credential` WS event so the UI stays current. Because the secret
material is encrypted at rest and redacted on read, a holder of `can-view` can
see which sources a credential covers (its `prefix`) but not the token or key
itself.

## Design decisions (folded into AGENTS.md / Architecture.md)

- **The source-credential API is CRUD with encrypt-on-write and redact-on-read.**
  `GET/POST /api/source-credentials` and `GET/PUT/DELETE
  /api/source-credentials/{name}` manage `SourceCredential` rows (F-21.3.1);
  the API encrypts the plaintext secret material on create/update (via the F-12
  store) and redacts it on read, so the plaintext is never returned to the UI.
  Listing requires `source-credentials.can-view`; create/update/delete require
  `source-credentials.can-manage` (admins have both). A change publishes a
  `source_credential` WS event so the UI stays current.
- **New endpoints / permissions (this sub-feature).** `GET/POST
  /api/source-credentials` and `GET/PUT/DELETE /api/source-credentials/{name}`
  (api); a `source-credentials.can-view` / `source-credentials.can-manage`
  permission pair (F-14); and a `source_credential` WS event.
