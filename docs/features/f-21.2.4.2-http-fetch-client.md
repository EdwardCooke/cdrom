# F-21.2.4.2 · HTTP fetch client

> Part of [F-21.2.4 · Fetch clients](f-21.2.4-fetch-clients.md) · Part of [F-21.2 · Source-fetcher service](f-21.2-source-fetcher.md) · Part of [F-21 · Config as code](f-21-config-as-code.md) · Phase 4 — Delivery & observability · [Feature index](../Features.md)

**What.** The **`http` fetch client** — the client that serves an `http`
reference (F-21.2.2) by doing a GET of the endpoint that serves the definition
file (e.g. an object-store URL or a raw-file endpoint) and using the response
body as the file. Request headers come from the source's `http` credential
(F-21.3) — a `token` sent in a configurable `header`, default
`Authorization: Bearer <token>` — so a credential is **optional**: an endpoint
that needs no authentication is fetched with a plain GET. The client returns
the `ETag`/`Last-Modified` as the version identifier and the SHA-256 of the
body as the content hash.

**Why.** Isolating the HTTP fetch in its own client keeps the rest of the
service (the gRPC contract, F-21.2.1) thin and makes the HTTP-specific behavior
— the GET, credential-supplied headers, and the `ETag`/`Last-Modified` version
identifier — a single, testable unit.

**Scope.**
- The **`http`** client in `internal/services/pipelinesource` — a GET of the
  endpoint; the response body is the file.
- Credential application — request headers come from the source's `http`
  credential (F-21.3); a credential is optional (a public endpoint is fetched
  with a plain GET).
- The version identifier — the response's `ETag`/`Last-Modified`.
- The content hash — the SHA-256 of the response body.

**Acceptance criteria.**
- [ ] A file can be fetched from an **HTTP/HTTPS** endpoint (a GET whose
      request headers come from the source's `http` credential — a credential
      is optional).
- [ ] The **`http`** client does a GET and uses the response body as the file;
      request headers are supplied by the source's `http` credential (F-21.3 —
      a `token` sent in a configurable `header`, default
      `Authorization: Bearer <token>`); there are no in-band headers on the
      reference, and a credential is **optional** — an endpoint that needs no
      authentication is fetched with a plain GET.
- [ ] The client returns the response's `ETag`/`Last-Modified` as the version
      identifier and the SHA-256 of the response body as the content hash.
- [ ] A fetch failure (unreachable endpoint, a non-2xx response, auth failure)
      returns a clear gRPC error the API can surface on the source's state
      (F-21.5).

## The http fetch client

The `http` client serves an `http` reference (F-21.2.2) — a full URL — by doing
a GET of the endpoint that serves the definition file (e.g. an object-store URL
or a raw-file endpoint):

- **The GET.** The client issues a GET of the endpoint and uses the response
  body as the file's content.
- **Credential application.** Request headers are supplied by the source's
  `http` credential (F-21.3) — a `token` sent in a configurable `header`,
  default `Authorization: Bearer <token>`. There are no in-band headers on the
  reference, and a credential is **optional**: an endpoint that needs no
  authentication is fetched with a plain GET.
- **Version identifier.** The response's version identifier is the `ETag`/
  `Last-Modified` header (whichever the endpoint provides).
- **Content hash.** The response's content hash is the SHA-256 of the response
  body.

## Design decisions (folded into AGENTS.md / Architecture.md)

- **HTTP headers come from the credential store.** An `http` fetch's request
  headers are supplied by the source's `http` credential (F-21.3), not in-band
  on the reference — so a credential is optional (a public endpoint is fetched
  with a plain GET). The `http` client does a GET, uses the response body as
  the file, and returns the `ETag`/`Last-Modified` as the version identifier.
- **New fields / RPCs / endpoints (this sub-feature).** The `http` fetch client
  in `internal/services/pipelinesource` (the GET, credential-supplied headers,
  the `ETag`/`Last-Modified` version identifier).
