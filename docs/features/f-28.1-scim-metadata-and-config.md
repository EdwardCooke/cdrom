# F-28.1 · SCIM metadata & service configuration

> Part of [F-28 · SCIM user provisioning](f-28-scim-provisioning.md) · Phase 6 — Authentication · [Feature index](../Features.md)

**What.** Mount the **SCIM 2.0** (RFC 7643/7644) service-provider surface on
the built-in IdP's existing HTTP server — alongside the OIDC surface
(discovery, JWKS, `/auth`, `/token`) under the **fixed** base path `/scim/v2`
— and serve the three metadata endpoints every SCIM consumer hits first: `GET /scim/v2/ServiceProviderConfig`, `GET /scim/v2/Schemas` (plus
`/Schemas/{schemaUri}`), and `GET /scim/v2/ResourceTypes` (plus
`/ResourceTypes/{resourceType}`). This sub-feature also introduces the
**`idp.scim` configuration object** that steers the whole feature family:
enablement, the public-base announcement, the SCIM service credential
(consumed by F-28.2), the page bound, and the group→role mappings (consumed
by F-28.5). The resource endpoints
(`/Users`, `/Groups`) belong to F-28.4/F-28.5; this piece ships the frame, the
handshake, and the switches.

**Why.** Corporate IdPs probe `ServiceProviderConfig` before syncing to learn
what the provider supports (patch, filter, bulk, pagination bounds). Serving
accurate capability ads — honestly claiming `bulk`/`etag` unsupported until
they land — keeps consumers from driving behaviour we don't implement. Putting
every knob in one config object keeps the feature switch, the credential, and
the mapping policy colocated and easy to reason about across IdP replicas.

**Scope.**
- `internal/idp` (new `scim.go`) — the SCIM router mounted on the IdP's HTTP
  mux when `idp.scim.enabled`: the `/scim/v2` subtree, `application/scim+json`
  content negotiation, the SCIM error-body encoder (RFC 7644 §3.7 shape:
  `schemas: urn:ietf:params:scim:schemas:core:2.0:Error`, `detail`, `status`)
  shared by all F-28.x handlers, and the three metadata responses:
  - **`ServiceProviderConfig`** — `schemas: […:ServiceConfiguration]`,
    `meta.resourceType: "ServiceConfiguration"`, `patch.supported: true`,
    `filter.supported: true`, `bulk.supported: false`, `etag.supported: false`
    (flipped when the nice-to-haves land), `pagination.maxResults` /
    `filter.maxResults` reflecting the configured page bound
    (`idp.scim.max_page_size`, default 100, hard-capped at 10000).
  - **`Schemas`** — the core `User`, `Group`, and `Error` schema URNs;
    URN-addressed retrieval returns the individual descriptors.
  - **`ResourceTypes`** — `User` → endpoint `/Users`, `Group` → endpoint
    `/Groups`, each linked to its schema URN.
- `internal/config` — the `idp.scim` section on `IdPConfig`: `Enabled`
  (default `false`), `PublicBase` (the base URL the surface ANNOUNCES to the
  outside world — `meta.location` / `changeInfo.location`, and from F-28.4
  `Location` headers; empty = derive per request from Host/X-Forwarded-Proto,
  set = pinned, must be an absolute http(s) URL — validated at load),
  `Credential` (the SCIM service bearer token — consumed by F-28.2, never
  logged or displayed), `MaxPageSize` (page bound; default 100, hard-capped
  at 10000), and `GroupRoleMappings` (SCIM group display name → F-14 role
  name — consumed by F-28.5). Env overrides follow the existing `CDROM_IDP_*`
  convention (`CDROM_SCIM_ENABLED`, `CDROM_SCIM_PUBLIC_BASE`,
  `CDROM_SCIM_CREDENTIAL`, `CDROM_SCIM_MAX_PAGE_SIZE`,
  `CDROM_SCIM_GROUP_ROLE_MAPPINGS`).
- Behaviour when disabled: the `/scim/v2` subtree is simply not mounted — all
  SCIM paths 404 and nothing is exposed.

**Design decisions.**
- **Metadata is behind the same caller-auth gate as the resources** (F-28.2):
  corporate IdPs present the SCIM credential on every request, including
  probes. Nothing under the base path is publicly readable.
- **Capability ads are conservative**: only `patch` + `filter` are claimed at
  launch; `bulk` and `etag` advertise `false` until implemented, keeping the
  metadata honest.
- **Fixed mount, flexible announcement.** WHERE the IdP listens (`/scim/v2`)
  is a flat literal — native mux patterns, predictable, no operator-supplied
  text feeding the pattern grammar. WHERE the outside world believes the
  surface lives is a separate axis: `public_base` pins the announcement when
  the exposure diverges from reception (prefix-stripping proxies, external
  DNS, branded portals); when unset, announcements derive per request
  (Host + X-Forwarded-Proto) and cover transparent-proxy setups. Announcements
  inform clients; they steer no routing.
- **The SCIM surface lives on the IdP's HTTP listener** (default port 7104);
  the API is not in the SCIM-serving path (parent decision).

**Acceptance criteria.**
- [x] With `idp.scim.enabled: true`, the IdP serves `GET /scim/v2/ServiceProviderConfig`,
      `/scim/v2/Schemas`, and `/scim/v2/ResourceTypes` with
      `application/scim+json` bodies shaped per RFC 7643 §6/§7.
- [x] With `idp.scim.enabled: false` (the default), every `/scim/v2/*` path
      returns 404 and no SCIM routes are registered.
- [x] `ServiceProviderConfig` advertises `patch` and `filter` support,
      declines `bulk` and `etag`, and publishes `maxResults` equal to the
      configured page bound (default 100; `idp.scim.max_page_size` raises it,
      clamped at the 10000 hard cap).
- [x] `Schemas` lists the core `User`, `Group`, and `Error` schemas;
      `ResourceTypes` maps `User` → `/Users` and `Group` → `/Groups`.
- [x] The `idp.scim` config object loads from the YAML section and env
      overrides with the documented defaults; the credential value never
      appears in logs, metrics, or any API/UI surface.
- [x] The SCIM error-body encoder produces RFC 7644-shaped errors (exercised
      by forcing a 404 under the base path).
- [x] Announcements honor `idp.scim.public_base` when set (pinning ignores
      the request's Host) and derive per request (Host/X-Forwarded-Proto)
      when unset; a relative or non-http(s) `public_base` is rejected at
      config load.
