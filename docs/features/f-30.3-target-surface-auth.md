# F-30.3 · Target-surface authentication & transport

> Part of [F-30 · Agent credentials & the agent/worker topology](f-30-agent-credentials-and-topology.md) · Phase 8 — Target credentials & execution topology · [Feature index](../Features.md)

**What.** The CONSUMING side: the API's gRPC target surface authenticates
callers by **agent credential** instead of trust-the-transport. Every target
RPC requires `Authorization: Bearer <agent-credential>`; the API verifies
the signature against the IdP's JWKS and gates liveness on the credential
ROW (F-30.2), so **revocation takes effect within one heartbeat** without
disturbing running jobs. The agent↔API transport drops mutual TLS in favor
of ordinary TLS (server verification) + the JWT; the internal service mesh
keeps mTLS. Job-token-presented RPCs are UNCHANGED — the two schemes coexist
per-RPC by verb, exactly as job tokens and mTLS coexist today.

- **Presentation.** Every target RPC (`RegisterAgent`, `WatchJobs`,
  `Heartbeat`, `ListPendingJobs`, `StartJobExecution`, `ReportJobStatus`,
  `ReportStepCompletion`, `CheckStepBarrier`, `CheckApproval`,
  `StreamJobLogs`, artifact-proxy RPCs, and — arriving with F-30.4 —
  `ReportChildDeath`) requires the credential. Agents present JOB TOKENS on
  job-scoped verbs; a verb never mixes the two.
- **Verification.** Signature via the IdP JWKS (discovery + cached keys —
  the existing `JobTokenAuth` pattern generalized into a SHARED verifier
  used by both credential and job-token paths). Liveness via the `jti` row
  through the Database service, **short-TTL cached** (positive ≤ 30 s,
  negative UNCACHED) — revocation therefore bites within cache TTL + one
  heartbeat. Throttled `last_seen_at` updates feed the UI's "seen recently"
  indicator.
- **Registration binding.** `RegisterAgent` asserts
  `request.name == credential.sub`; mismatch ⇒ `PERMISSION_DENIED`. A
  stolen credential cannot masquerade as a different agent. Group,
  environments, and labels remain REGISTRATION DECLARATIONS (validated as
  today), unconstrained by the credential.
- **Streams.** `WatchJobs` validates at OPEN; the heartbeat loop
  revalidates CONTINUOUSLY and the API aborts the stream on a failed
  revalidation (dead `jti`, expired row). No mid-message renegotiation.
- **Transport.** Agent↔API: TLS with SERVER-CERT VERIFICATION (agent config:
  `ca_file` for the API's serving cert) + bearer JWT. Client certificates
  are **removed from this leg** (`grpcutil` gains a non-mutual dial
  variant). Scheduler↔DB↔IdP↔artifacts↔pipelinesource KEEP mTLS. The
  plain-text fallback for local dev behaves as today — legitimate because
  the *credential CHECK*, not the cipher suite, is the identity guarantee.
- **Credential sourcing.** The agent obtains its JWT from its **credential
  file** (config `credential.file`, F-30.2 Distribution) — parsed at boot,
  watched for atomic overwrites, and adopted live on change (a rotated token
  takes effect on the next RPC without a restart). The environment is NOT a
  legal source: the token must never sit in `CDROM_*` vars (process-listing
  exposure + inheritance into worker subprocesses, violating F-30.4). A
  missing/unparsable file is a boot refusal with a diagnostic.
- **Toggle.** Enforcement follows the existing auth-posture knobs
  (`grpc.auth` family): when the IdP is wired and agent-credential auth is
  enabled, target RPCs lacking a valid credential are `UNAUTHENTICATED`.
  Shipped configurations ENABLE it; there is no legacy bypass mode.
- **Consumer-side effects of rotate/revoke/lapse** (semantics owned by
  F-30.2): the API tears down affected watch streams and rejects heartbeats
  bearing dead `jti`s; the agent adopts its successor within the
  watch-backoff (≤ 2 s) and the poll path (F-23) recovers any assignments
  missed meanwhile; IN-FLIGHT WORKERS ARE UNAFFECTED (job tokens are
  orthogonal). A lapsed credential ends in non-zero exit + supervisor
  restart (F-30.2 Lapse).

**Why.** Targets live OUTSIDE the service mesh; handing them mesh client
certificates is the bootstrap friction this removes, and ordinary TLS +
bearer JWT is the portable norm. Tracking the credential in the database
(governed by F-30.2's row) buys instant, auditable revocation — the thing
"a client cert" could never offer.

**Slices.** Sequential increments, each ending compiled, tested, and
demonstrable (checkpoint commit per slice):

- **Slice 1 — Shared verifier.** The generalized verification primitive
  (JWKS discovery/key cache + row-liveness lookup via the Database service
  + the short-TTL cache + throttled `last_seen_at`), factored so BOTH the
  agent-credential path and the existing job-token path use it.
  Demonstrable: unit tests — genuine signature passes; forged signature,
  wrong audience, revoked row, and expired row all reject; cache TTL
  behavior measured (negative results never cached; positive hits within
  TTL skip the DB).  _(LANDED: `internal/api/tokenverifier.go` — the SHARED OIDC substrate
  (`newOIDCTokenVerifier`: discovery + SkipClientIDCheck + SkipExpiryCheck,
  the documented cdrom machine-token policy) and `audienceAccepted`, now
  used by BOTH `JobTokenAuth` and `AgentCredentialVerifier` (their divergent
  copies deleted). `AgentCredentialVerifier` rebuilt on it with the
  LIVELINESS CACHE: positive verdicts cached ≤ 30 s keyed on (jti, bound
  name) — the name guard defeats a poisoned/stale entry; NEGATIVES UNCACHED
  (a flipped row is reconsidered immediately, and a fresh negative discards
  any stale positive); opportunistic sweep of expired entries. Injected
  CLOCK makes TTL behavior MEASURABLE. Verified presentations bump
  `last_seen_at` THROUGH the Database service at most once per 60 s
  (throttle; best-effort — never affects the verdict). Measured in
  `agentcred_cache_test.go`: 3 verifies = 1 lookup (within TTL), TTL expiry
  forces a refetch, 3 denials = 3 lookups (stickiness absent), un-revocation
  honored immediately, poisoned-entry defeat, and the mark-throttle curve
  (t0 mark, t0+30 s suppressed, t0+90 s mark). Existing credential +
  job-token suites pass unchanged against the refactored paths.)_
- **Slice 2 — Mandatory presentation + binding.** Guards installed on EVERY
  target RPC (the verb list above minus `ReportChildDeath`, which lands
  with F-30.4); `UNAUTHENTICATED` semantics; the `RegisterAgent`
  name-binding assertion. Demonstrable: integration tests — an uncredentialed
  target RPC is rejected; registering under a name ≠ the credential's `sub`
  is `PERMISSION_DENIED`; the credentialed happy path (register → watch →
  heartbeat → start → report) is green.
- **Slice 3 — Streams + transport.** `WatchJobs` open-validation +
  heartbeat revalidation + stream abort; the non-mutual dial variant in
  `grpcutil`; the agent's `ca_file` config; CLIENT CERTIFICATES OFF THE
  LEG; the auth-posture toggle wired (enabled in shipped configs).
  Demonstrable: e2e — REVOCATION MID-SESSION: the owning agent's heartbeat
  fails and its watch stream tears down within one heartbeat + cache TTL,
  and it cannot re-establish identity without a valid credential;
  ROTATION: adopting the successor reconnects the watch stream within the
  backoff while in-flight jobs complete untouched.

Dependency: S1 → S2 → S3 strictly. Requires F-30.2 S1+S2 (something to
verify and something to administer); F-30.2 S3 (self-service renew) pairs
naturally with S3's rotation e2e.

**Scope.**
- `internal/api` — the target-surface guards (interceptor/dispatch checks),
  the watch-hub stream-abort hook, `RegisterAgent` binding.
- `internal/grpcutil` — non-mutual (server-verified) dial variant.
- `internal/config` — agent `ca_file`, `credential.file` (required; the
  agent sources its token from this file), and the auth-posture knobs for
  agent-credential enforcement.
- `internal/idp` — JWKS publication (existing) exposed to the shared
  verifier.

**Design decisions.**
- **Orthogonality by verb.** Agent credentials authorize TARGET-SURFACE
  verbs; job tokens authorize JOB-SCOPE verbs. No verb accepts both — the
  split keeps blast radii disjoint (a leaked job token compromises one job;
  a leaked agent credential compromises one agent, and is instantly
  revocable).
- **Positive-cache ≤ 30 s, negatives uncached.** Trades microsecond-cheap
  verification for bounded revocation latency (cache TTL + one heartbeat);
  revocations are rare and emergencies, staleness is cheap.
- **No mid-stream renegotiation.** Tokens are checked at open and via the
  heartbeat cadence; a stream never switches principals mid-life.

**Acceptance criteria.**
- [ ] A JWT's `sub` is `agent:N`; presenting it to `RegisterAgent` with any
      OTHER name is rejected (`PERMISSION_DENIED`).
- [ ] Revoking (or expiring) a credential causes the owning agent's
      heartbeat to fail and its `WatchJobs` stream to tear down within one
      heartbeat + cache TTL; the agent cannot re-establish identity without
      a valid credential.
- [ ] Rotating yields a successor JWT; adopting it reconnects the watch
      stream within the backoff; in-flight workers continue on their job
      tokens throughout.
- [ ] Agent↔API runs over TLS-with-server-verification + bearer JWT (NO
      client cert on that leg); internal services still negotiate mTLS.
- [ ] Target RPCs without a valid credential are `UNAUTHENTICATED` under
      the shipped (enabled) posture; job-token verbs are unaffected.
- [ ] The agent sources its token from the credential FILE (not the
      environment): it boots, registers, and serves jobs from the file; a
      missing file refuses boot; an atomic overwrite with a rotated JWT is
      adopted live (next RPC succeeds) with no restart. The file is written
      atomically (DOT-PREFIXED temp + rename, `0600`) via the shared
      `internal/credfile` primitive (landed in F-30.2), whose temp naming
      lets the watcher ignore in-flight writes; the JWT never appears in logs,
      argv, or any child process's environment.
- [ ] AUTO-RENEW WINDOW (carried over from F-30.2): the agent's renew-ahead
      timer fires within its configured window before the row's deadline and
      calls the self-service renew endpoint (F-30.2 Slice 3); the extended
      deadline is honored, and renew failures back off and retry WITHOUT
      tearing down the stream.
- [x] Verified presentations bump `last_seen_at` (throttled) and surface in
      the credential listing.
      _(Slice 1: `markSeenThrottled` bumps via the Database service at most
      once per 60 s window (curve measured in `TestLastSeenThrottle`); the
      listing (F-30.2 Slice 2) already renders `last_seen_at` from the row._)
